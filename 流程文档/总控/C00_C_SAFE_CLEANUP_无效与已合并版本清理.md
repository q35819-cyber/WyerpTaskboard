# C00_C_SAFE_CLEANUP｜开工前快速清理检查

- **准入**：`C00_B_MAIN_VERSION` 已核对正式主线与软件版本。
- **执行（取代旧‘只盘点等待闲时’规则）**：每次开工从真实任务历史、冻结候选、Git及占用记录自动扫描，按**有效待交付、已完成可清理、已完成需归档、需保全复核**四类逐项处置。正式独测PASS待交付由总控走C04；已完成且远端main包含提交、完全干净无人引用的本地分支/工作区用非强制Git命令清理；已完成而旧候选SHA不在main，但已被正式QA PASS版本替代或补丁等效者，**保留SHA、先校验无绑定工作区及未关闭PR引用，再以非强制`git branch -m`迁至本地`archive/`**，记录原/新ref、SHA、替代候选、归档原因；仍有独有修复的旧提交保留审计并派原责任核对，不直接合并或删除。证据不足者保全并记阻断、owner、下次触发条件；不动远端引用、未提交/未跟踪成果、其它AI工作区。
- **最新覆盖：自动安全清理而非仅盘点**：前文“开工仅快速盘点，深入清理等闲时”不再作为完成条件。C00_C每次基于正式任务历史和Git现场扫描遗留资源：已在远端main、任务正式关单、工作区完全干净且无AI/Session/Job/PR/共享引用、报告备份已保全者，当前轮次直接执行非强制安全清理、读回并写本项目日志。未满足的保全，记录原资源、原因、责任角色和下一C00/C07/C08触发条件；下一触发自动复核、失败可重试且幂等。已独测PASS待交付件移交总控C04处理；不得绕过QA而自动提交合并，也不得强删未提交成果、未知所有权远端分支或影响其他AI。
- **增量复核性能边界**：不要求每次对全部历史工作区逐一深度清理。已归档且原任务/引用/工作区状态与上次审计一致的项可凭SHA与事件记录跳过昂贵复查；**新增、上次清理失败、前置已解除或引用发生变化的资源必须在本轮真实执行或重新保全登记**，不得因增量优化永久滞留。
- **证据**：快速盘点的路径、状态、遗留清理清单；实际深度清理命令/退出码/审计日志。不冲突的开发/独测无需因无害历史目录被阻断。
- **PASS下一步**：`C01_SCAN`。必须有逐类实际清理/归档结果或不可操作项的保全与续办证据；仅‘已检查’不是清理PASS，归档旧候选不代表代码已合并。
- **程序兼容**：本步骤为文件职责要求，stepctl原子门禁仍待合法集成。
