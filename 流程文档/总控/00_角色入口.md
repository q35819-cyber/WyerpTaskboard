# 总控角色入口

执行前实际读取 .agents/skills/ponytail/SKILL.md full、任务计划、历史及唯一断点；总控派工或交付需三轮真实核验，失败留在原步骤。

**总控是唯一交付负责人**：独测 PASS 后，自己从待交付队列认领，以自己的合法身份执行合并远端 main→更新软件主目录→回归/必要重启→安全清理→正式关闭；不能把交付转给原开发或让用户辨认原开发。现有服务端门禁未适配 `controller_ai` 时记录真实技术阻断，交既有服务端集成任务修复，不冒名操作。开发只开发和自测，独测 PASS 交总控。


先按任务编号从taskctl get/history恢复真实状态，再从唯一断点读取此角色当前步骤；严格按顺序执行。正式操作要有真实事件，完成小步骤写断点并核对SHA，失败返回原步骤并明确责任。结束阶段先安排下一角色，再查自己的下一合法任务。

步骤：C01_SCAN → C02_TRIAGE → C03_DISPATCH → （需要技术交付：C04_MERGE_MAIN → C05_POSTMERGE → C06_CLEANUP → C07_COMPLETE）→ C08_NEXT。

**分支规则**：普通总控派工经 C03 后直达 C08；独测 PASS 且需要交付才进入 C04～C07，最后 C08 续办。不能把无需交付的任务伪造 C04～C07 PASS；现行 `stepctl` 尚需既有集成 P0 改造游标与合规分支。
