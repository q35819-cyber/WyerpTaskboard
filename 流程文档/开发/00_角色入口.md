# 开发角色入口

**开发四并发、连续续接与同任务唯一占用（2026-11-07，最新优先）**：最多安排 4 个开发 AI 并行，但**必须是 4 个不同的完整任务编号**。独立 worktree 是不同任务之间的文件隔离手段，**绝不是允许两名开发同时开发同一张任务的理由**；同一任务在任一时刻只能有一个有效的开发 actor-id、Session 和工作区。每名开发先读原路径 `data/taskboard/checkpoints/00_跨角色共享待办_总控维护.md`，自上而下只选未被其他有效开发认领、真正可执行的任务；已经开发中且有有效负责人的一律跳过到下一张，不重复 claim、不在另一个工作区平行开发同一个编号。正式领取后处理最小代码、三轮自测、正常交唯一独测；**交测即继续按原清单领取下一张不同且可做的任务，不必空等前一张独测或总控合并**，直到当前可领取任务耗尽。一个任务遇到当前规则/前置阻断，不得停住全部开发队列，记录该任务错误后继续下一项；不自行新增任务、不自行修改总控清单，也不自动唤醒休眠 AI。

**用户授权的 5 分钟异常接管是替代，不是并行**：若某张正在开发的任务连续超过 5 分钟**没有真实文件修改或其他可信执行进展**，由接手开发自行检查原工作区 Git、文件变化、断点、事件和活跃会话。确认异常后才按本轮用户授权办理**唯一异常接管**：先取得系统认可的接管资格，原 actor/Session 的任务执行权必须被撤销或经合法原子接管替换，新开发保留全部原候选、修改和失败记录后接续，旧开发不得重新写同任务。仅“不同 worktree”、仅超时或仅写一条授权 note 都不算完成接管；系统仍显示原有效占用时不得第二个普通 claim，更不得两人同时改同一任务。拒绝/409/门禁失败要保留实际错误并**立即继续找下一张不同任务**；不能倒填步骤、伪造 PASS 或绕过唯一独测/总控交付。每次聊天明确输出所接完整编号、是否与其他开发重复、工作区、接管前后 actor/Session、下一张完整编号。

**规则版本：`2026.11.03-r1`。必读校验**：进入本角色前第一份必须读取 `流程文档/00_流程与重大更新日志.md`，与该日志当前生效版本和 `流程文档/00_统一入口.md` 比较。若不一致、缺失或有新重大更新影响职责，暂停执行并重读最新统一入口、本角色完整规则/有关步骤、操作审计规范、任务历史和唯一断点，合法更新后再开工。任何源码/文件/配置变更和程序运行 CRUD 均须在**所属项目目录**留下真实审计日志（`流程文档/02_增删改操作日志规范.md`）。


**所有项目通用纪律**：软件正式发行版采用主版本.次版本.修订号（如0.0.0），重大功能第一位、普通功能第二位、BUG修复第三位；任何讨论的需求先落本项目需求池，开发/独测只核验对应已批准的任务与版本，不将未合并候选当正式版本。规则参见 流程文档/01_主目录版本与安全清理规范.md、流程文档/03_版本号与需求记录规范.md。不得擅自删除有其他AI占用的分支或资料。

**开发并行合法接单是强制职责**：用户手动唤醒、收到总控派工或D09成功handoff释放占用后，在**同一已唤醒会话**先找本人历史actor的独测FAIL返修（别人FAIL不可冒领），再遍历所有具备正式资格的其它开发候选；每张任务必须完成真实`get/history/guard → preclaim-report → claim`及读回，不得只完成scan/计划检查就停止。合法claim后在自己**独立干净Git worktree**写代码，不能编辑其它actor工作区；相同文件名不自动等于禁止并行，实际未完成依赖、STOP、角色权限、真实共享资源或本actor已有任务必须遵守门禁。遇到409 `CLAIM_WRITE_CONFLICT`/`CHECKPOINT_STEP_ORDER`/工具安全限制，不绕过或伪造成功：记录命令/退出码/事件和实际被挡文件/责任，交总控原P0修门禁，**继续尝试其它合法候选**；所有候选皆阻断时才保存断点并结束，不能反复等用户发“继续”。单开发actor一次一任务，唯一独测及main合并串行；本条规则已落文件但服务端claim/旧断点新轮次仍待独测交付。

**最新开发领取顺序（优先于旧链头排序）**：用户手动唤醒或D09续接时，先查看阻断/独测失败待修复任务，核对正式历史actor_id是否属于自己原开发；属于本人且合法准入就优先返修；属于别人跳过，除非用户或总控按规则授权异常接管。没有本人返修再扫描「待执行」列（所有硬前置完成、无STOP和占用），按用户加急/下游解锁能力/P0等合法排序，通过guard/preclaim/claim正式领取。其它开发AI在不同worktree可并行；同actor一次一项。此状态和自动选领仍是待交付开发目标，当前必须真实自行查队列，不得假称程序已自动认领。

**自主领任务的前置优先职责**：开发AI被用户唤醒或完成D08后续接D09时，主动读取全项目真实待开发队列/依赖及当前占用；**优先领取已具备准入且能解锁更多下游任务的最前置任务**，缺失/未完成前置的下游必须报告阻断、不可冒领。不同开发AI使用独立Git worktree并行处理无未完成前置的任务，不因其它工作区正修改同名文件就放弃开发；本actor/Session同一时刻只认领一项，代码从独立候选交独测、main仍串行合并。现有自动选领和跨工作区认领服务端门禁尚待原任务开发，当前须主动执行真实list/guard/preclaim/claim，不得将文档规定冒充程序已经自动认领。

**逐步聊天报告硬要求**：每一步执行前必须在当前聊天窗口报告任务号、角色、步骤、Ponytail实际读取路径及模式、拟用工具和动作；重要工具实际调用后即时汇报结果，结束时报告PASS/FAIL/BLOCK、命令/退出码、变更文件与SHA、事件/断点、下一步。遇到异常先立即报告，不能最后只写总结，更不能虚报已读Skill或执行成功。详见 `流程文档/04_逐步聊天汇报与证据校验规范.md`。服务端目前没有可信聊天送达回执，不能把操作日志当作用户已看到消息，程序最小门禁归原P0任务。

先按任务编号从taskctl get/history恢复真实状态，再从唯一断点读取此角色当前步骤；严格按顺序执行。正式操作要有真实事件，完成小步骤写断点并核对SHA，失败返回原步骤并明确责任。结束阶段先安排下一角色，再查自己的下一合法任务。

**三轮开发自测要求**：每次代码或修复均须分别验证①核心正常路径②错误/边界/数据保全③相关既有功能与跨项目/重启集成，三轮各自保留真实命令、退出码、证据、候选SHA；不能把同一命令重复三次或开发PASS代替独测。执行中发现工具/依赖/运行环境异常要上报总控按C00_D核查与安装，不私自扩大为全平台重构。

**执行步骤**：D01_CLAIM → D02_WORKTREE → D03_WRITE_SCOPE → D04_IMPLEMENT → D05_TEST_1 → D06_TEST_2 → D07_TEST_3 → D08_HANDOFF → D09_NEXT；交独测成功后开发释放占用并继续自己的开发队列，独测 FAIL 时回原开发修复，PASS 由**总控 AI**负责交付。

**程序兼容提示**：D09～D12 交付文件已从开发目录移走，实际开发目录只保留 D01～D09（D09=续接）。但现行 `stepctl` 仍使用旧开发交付游标，需 `WTB-P0-ROLE-STEPS-SERVER-GATES-20261102-T1` 同步修改程序门禁、游标及测试；未改好前不得伪造PASS或冒用身份。

**2026-11-05 全软件 BUG 必修（覆盖普通接单）**：每次唤醒/D09 续接先全文读取 `流程文档/07_全软件BUG强制修复与闭环续接规范.md`；先本人合法 FAIL 返修和所有可合法 claim 的 P0 BUG，实做 get/history/guard、preclaim、claim、独立修复和三轮自测，不可只汇报或停止。遇 409、旧断点、资源占用必须记录真实证据、关联最小根因 P0，继续尝试下一合法 BUG，不得跨身份或绕过 STOP/QA。
