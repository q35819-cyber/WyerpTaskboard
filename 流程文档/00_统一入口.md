**正式归属**：统一流程权威源始终是**任务看板仓库根目录相对路径** `流程文档/`。独立 Git worktree 仅供隔离开发和独测，绝不是固定安装路径；项目无论移动到哪个盘符，均先定位当前项目根目录，再以相对路径解析。

**相对路径强制规则**：流程、角色、任务计划、断点、通用模板与示例配置中的文件/目录引用一律用以对应项目根目录为基准的相对路径（`流程文档/开发/00_角色入口.md`、`data/taskboard/checkpoints/<TASK-ID>.md` 等）；禁止任何本机盘符路径、UNC共享绝对路径和用户主目录绝对路径。程序运行时可解析为系统绝对路径进行真实文件操作，但对外显示与持久化的可迁移路径必须保持项目相对路径。Git远端URL、外部参考网址不属于本地文件路径。

**通用模板**：`templates/webcodex-v1/流程文档/` 为本目录逐文件一致的发布副本，供其他项目手工接入时复制到各项目 `流程文档/`；**只在本目录修改流程，发版时同步模板并核对全部文件内容哈希**，禁止两处独立维护互相矛盾的规则。各项目任务实际状态/断点仍以任务看板注册表和各项目按任务编号的 checkpointDir 为准，不复制任务数据或事件记录。

一任务编号只用项目配置 checkpointDir 下的 `<任务编号>.md`。总控、开发、独测每完成可验收小步骤都先写断点并读回。PASS才能执行下一步，FAIL/BLOCK停留原步骤；涉及正式任务状态的claim/handoff/test-result/complete必须引用真实事件。

**并行开发的执行责任（用户2026-11-03最新确认）**：总控每次被唤醒及C03先扫描本项目全部开发候选、原开发独测FAIL及依赖链，**一次性正式派发所有当前能够合法并行的任务**，每项记录任务ID、原因/前置、责任角色、空闲窗口下一动作、正式事件并读回，不因一个P0阻断而让不相关任务等待，也不把派工当认领成功。已被唤醒的开发AI在D01/D09按原FAIL优先→其它合法候选实际执行 `get/history/guard → preclaim-report → claim`，一个claim失败须记录具体错误并尝试其他可领任务，不得只扫描或反复向用户索要“继续”；其他AI由用户手动唤醒，不得自动启动。一个developer actor仅持一单；不同开发独立worktree允许并行，**真实未完成依赖/STOP/同一actor冲突/非法接管仍必须阻止**，目前服务端仍有过宽`CLAIM_WRITE_CONFLICT`程序缺口，交既有门禁P0按开发自测、独测、总控发布修复；同名文件冲突在受控main串行合并时解决，不覆盖他人工作区。待执行列只派生展示，不通过手工改业务状态搬卡片。
