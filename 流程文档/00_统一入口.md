# 三角色顺序执行统一入口（v1）

**正式归属**：统一流程权威源始终是**任务看板仓库根目录相对路径** `流程文档/`。独立 Git worktree 仅供隔离开发和独测，绝不是固定安装路径；项目无论移动到哪个盘符，均先定位当前项目根目录，再以相对路径解析。

**相对路径强制规则**：流程、角色、任务计划、断点、通用模板与示例配置中的文件/目录引用一律用以对应项目根目录为基准的相对路径（`流程文档/开发/00_角色入口.md`、`data/taskboard/checkpoints/<TASK-ID>.md` 等）；禁止任何本机盘符路径、UNC共享绝对路径和用户主目录绝对路径。程序运行时可解析为系统绝对路径进行真实文件操作，但对外显示与持久化的可迁移路径必须保持项目相对路径。Git远端URL、外部参考网址不属于本地文件路径。

**通用模板**：`templates/webcodex-v1/流程文档/` 为本目录逐文件一致的发布副本，供其他项目手工接入时复制到各项目 `流程文档/`；**只在本目录修改流程，发版时同步模板并核对全部文件内容哈希**，禁止两处独立维护互相矛盾的规则。各项目任务实际状态/断点仍以任务看板注册表和各项目按任务编号的 checkpointDir 为准，不复制任务数据或事件记录。

一任务编号只用项目配置 checkpointDir 下的 `<任务编号>.md`。总控、开发、独测每完成可验收小步骤都先写断点并读回。PASS才能执行下一步，FAIL/BLOCK停留原步骤；涉及正式任务状态的claim/handoff/test-result/complete必须引用真实事件。

开发AI各用自己的git worktree，按writeTargets保护同路径及父子目录；唯一独测按队列串行测试；main合并串行。合并→最新main回归→清理已合并工作区/分支→真正关闭，四者缺一不算完成。超24小时无真实进展，可由同角色新窗口按用户常设授权合法接管，不自动唤醒或假冒旧Session。



**唯一有效角色入口**：新任务和接入项目必须依次读取 `流程文档/00_统一入口.md`、当前角色的 `流程文档/<角色>/00_角色入口.md` 及断点指示的最小步骤文件。兼容 WORKFLOW.md 与短提示词仅跳转此处，不再存在另一套活动角色正文。历史内容仍保存在Git历史和非活动归档。

**共用执行底线**：所有角色开始执行前按 Ponytail `full` 阅读 `.agents/skills/ponytail/SKILL.md`、任务计划、真实看板历史、断点和 Git 占用；拒绝擅自扩大范围、过度开发或把独测建议无依据升级为需求。包括文档规则制定、代码开发和独立测试在内，均应在本角色正式交接前**执行三轮独立的本角色自查或测试并记录真实命令、结果和证据**；独测的三轮不得复制开发自测，更不能替代开发三轮。任意一轮失败，保留断点并退回本步骤；禁止冒用其它角色的PASS。

**用户职责边界**：用户只负责人工唤醒AI与最终UI、业务逻辑验收。总控安排任务、开发和独测执行技术门禁、Git推送与合并、回归、断点和清理均由AI负责，不要求用户派测试者、复制技术指令或处理合并冲突。禁止自动唤醒AI。

本目录是分步执行约定，新stepctl已可用；现有HTTP/taskctl旧入口的全部门禁还需后续受控集成，不能把文档或新断点CLI的PASS冒充全系统强制生效。
