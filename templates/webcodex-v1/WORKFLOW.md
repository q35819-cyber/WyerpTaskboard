# WORKFLOW.md — WebCodex 六步开发流程

本文件是唯一流程标准；其他提示词引用本文件，不重复维护状态规则。

## 1. 派发
总控创建任务，填写目标、允许/禁止修改范围、依赖、验收条件、测试命令、开发者、独测者和目标主分支。关键条件缺失不得开工。

## 2. 开发与自测
开发者认领任务，记录 Session、分支/工作区和起始 SHA。只修改任务范围。完成后运行指定自测。
自测证据包含：提交 SHA、命令、退出码、结果摘要、报告位置。任何代码变更都会使旧 SHA 的自测证据失效。

## 3. 独立测试
独测者必须不同于开发者。核对候选 SHA，独立取得该版本并执行验收。
报告包含：被测 SHA、实际命令、退出码、PASS/FAIL、失败复现步骤。不得复制开发者自测结果。

## 4. 失败回流 / 通过交付
FAIL：退回原开发者，保留报告和分支；修复后回到第 2 步。
PASS：进入“待交付”，保留原开发者的actor-id和Session作为认领约束，并自动生成合并待办。只有原开发者在原Session中可以认领；其他开发AI不得代领。

## 5. 合并与推送
原开发者负责：同步最新远端主分支；合并通过独测的候选 SHA；冲突解决后运行必要测试；推送远端；验证远端主分支包含实际合并提交。
若合并改变候选代码，必须重新自测和独测。
合并失败：保留分支、提交和现场。调用taskctl delivery-failed记录failure-stage、failure-code、原因和下一动作；任务保留“交付中”及原开发者占用，当前进度必须展示阻断信息，由原开发者在原Session继续处理。taskctl complete核验失败时CLI自动登记同类失败事件。

## 6. 合并后回归与关闭
对远端主分支实际 SHA 执行回归。只有远端包含合并提交、回归通过且版本记录更新，原开发者以原actor-id/Session执行taskctl complete后，才关闭任务并释放占用；核验失败会自动记录阻断原因。

## 唯一状态路径
待计划 → 待认领 → 开发中 → 待独测 → 独测中 → 测试失败待修复（失败）/待交付（PASS且需合并）/待用户验收（无需交付）→ 交付中 → 已完成。
每个任务任一时刻只有一个当前执行者和一个下一动作。待交付候选绑定原开发actor-id/Session；交付失败事件不得释放该占用。状态变更必须有看板事件，不能只改文字绕过门禁。

## 异常接管
用户明确要求接管时必须执行，不得以原 AI 未登记失联为由拒绝。记录用户原话、原/新执行者、原/新 Session、任务版本和工作区证据。
不删除原工作区或未提交修改。旧 Session 恢复后不得覆盖接管后的新版本；写入前核对任务版本/接管代次。

## 上下文切换
断点至少包含：任务 ID、状态、负责人、分支、起始/候选 SHA、自测/独测报告、未解决问题、下一动作。新 Session 先读断点和 Git 状态再继续。
