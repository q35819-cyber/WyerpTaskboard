# WORKFLOW.md — WebCodex 六步开发流程

**所有角色每一步必须实时向用户汇报**：操作前在当前聊天写任务/角色/步骤、Ponytail实际读取路径与模式、工具及具体动作；操作后立即写工具返回/退出码/异常，步骤结束写PASS/FAIL/BLOCK、断点与日志证据、下一步。不能只在最后总结或仅存看板事件，不得虚报已经读取Ponytail。详见 `流程文档/04_逐步聊天汇报与证据校验规范.md`；现有程序没有可靠的聊天送达回执，系统步骤证据不等于用户已看到，程序门禁尚需P0开发。


**六阶段总流程（所有软件）**：①用户讨论需求先记本项目需求池、有疑问先讨论；②总控确认规则版本、正式主线和快速安全盘点后派合法开发/独测；③开发隔离编码并三轮自测；④唯一独测FAIL退开发、PASS交总控；⑤总控合法合并main、升级实际软件、干净同SHA回归与实例验收、归档清理、关单；⑥总控核验反馈、记录版本与遗留需求并继续队列。每一阶段均有真实日志与任务断点，任何失败回到原责任流程，不增设其它角色。


**强制启动第一步（所有 AI / 每次新会话、接管、续办）**：先完整读取 `流程文档/00_流程与重大更新日志.md` 的当前生效版本与未读重大变更，核对 `流程文档/00_统一入口.md` 和本人 `流程文档/<角色>/00_角色入口.md` 的 **规则版本** 均匹配；版本不一致/日志缺失时，暂停领取和修改，重新读取最新统一入口、角色步骤、专项规范、任务历史及断点，完成合法版本对齐后才开工。此检查优先于旧聊天记忆及旧根角色文档。每次源码/配置/文件增删改及软件运行时 CRUD 都必须按 `流程文档/02_增删改操作日志规范.md` 写入**对应项目目录下**的持久日志，失败亦留痕；不得只写聊天、仅凭Git或向其它项目集中存储。


本文件仅是模板快速入口。唯一生效权威为流程文档中的最新版本与角色入口，不得以本文件摘要覆盖正式步骤。

**统一最小开发硬约束**：所有开发者先读取并实际执行项目内 `.agents/skills/ponytail/SKILL.md`（full）；先搜索原模块及调用方 → 复用现成代码/标准库 → 只做最小完整修改 → 检查 diff/必要回归；不添加需求外扩展、额外抽象、无用依赖和平台。总控派工需拒绝过度设计，独测检查 Ponytail 是否落实，不能用少代码逃避已知错误。


**所有接入软件的总控开工门禁**：先按 流程文档/总控/C00_A_REQUIREMENTS_需求记录与讨论.md 登记用户讨论需求；仅在用户明确新设备或真实环境异常时，由总控执行 流程文档/总控/C00_D_ENVIRONMENT_新设备与环境异常恢复.md 并按三种不同角度自测；正式认领/开发/交付前再核对 C00_B_MAIN_VERSION_主线与软件版本核验.md 和 C00_C_SAFE_CLEANUP_无效与已合并版本清理.md，随后进入C01_SCAN。保全主目录未提交与其它AI工作区；具体以最新流程文档/为准，不假报程序已自动实现。

## 1. 派发

**全项目强制**：启动首先读取 `流程文档/00_流程与重大更新日志.md` 并对比本人角色最新版本；不匹配重读规则及历史断点后再动手。任何程序代码/文件及运行时数据增删改必须在所属程序目录留真实日志，详见 `流程文档/02_增删改操作日志规范.md`。独测PASS交总控交付；新服务门禁尚未上线前不假报已生效。
总控创建任务，填写目标、允许/禁止修改范围、依赖、验收条件、测试命令、开发者、独测者和目标主分支。关键条件缺失不得开工。

## 2. 开发与自测
开发者认领任务，记录 Session、分支/工作区和起始 SHA。只修改任务范围。完成后运行指定自测。
自测证据包含：提交 SHA、命令、退出码、结果摘要、报告位置。任何代码变更都会使旧 SHA 的自测证据失效。
**强制最小步骤断点**：开始开发前实际读取最新角色规范、任务主计划、历史、失败报告、`data/taskboard/checkpoints/<TASK-ID>.md` 并与 Git/Job/Session 核对；每完成一个独立可验证的小功能立刻保存代码、记录专项自测与修改清单、更新断点并登记 checkpoint_saved，核验成功后才能开始下一个；异常、换窗口、Job 阻断同理。详细规则统一引用当前项目根目录 `流程文档/开发/00_角色入口.md`，不能等项目最后才一次性写断点。

## 3. 独立测试
独测者必须不同于开发者。核对候选 SHA，独立取得该版本并执行验收。
报告包含：被测 SHA、实际命令、退出码、PASS/FAIL、失败复现步骤。不得复制开发者自测结果。

**独测范围裁定**：验收以用户目标和派工时既定条款为准。独测 FAIL 要附真实复现及违反的条款；已约定的功能、兼容、数据/安全缺陷必须最小修复。独测发现超范围功能、想象场景或不确定风险，只记录并申请总控在原任务计划/事件中裁定“必须修 / 误报 / 新需求另议”，不得直接升级为开发任务或无限叠加测试。开发先核对范围再修，不能无条件执行独测的所有建议；总控应主动解释裁定给两方，不能忽略已证实的真实缺陷。

**各角色阶段完成立即续接**：核对真实事件和占用后扫描队列；总控合法派工，开发先接原actor独测FAIL返修，再接前置全部满足的候选（开发待执行列未上线），独测接正式待独测/待复测。逐项guard/preclaim/claim，不自动唤醒其它AI。

**阻断任务必须分流**：总控每次查 `阻断`、HOLD、长期待交付/交付中及失败事件；真实功能/CLI/服务Bug派原开发最小修，证据或SHA不符回原开发重新合法交独测，测试环境问题由责任人恢复，旧设备历史身份/证据缺失由总控核查合法恢复或用户授权接管（不得伪造）。每个阻断在原任务记录原因、下一角色、动作和解除条件，不能忽略或反复建重复任务。

**分支/worktree清理归总控**：独测PASS→总控合并推送→合并后回归PASS→正式taskctl complete关闭→检查已合并、干净、无运行Job/其它AI占用→安全移除本任务独立worktree、删除已合并本地任务分支（禁止强制删除）；远端任务分支仅在无未关闭PR/共享引用时受控删。记录实际清理或保全原因及退出码后继续下个开发任务。总控负责安全清理，独测不清理。不能借“清理”删除未合并/他人正在使用的工作区。

## 4. 失败回流 / 通过交付
FAIL：退回原开发者，保留报告和分支；修复后回到第 2 步。
PASS：有真实Git交付动作时进入“待交付”，保留候选SHA和原开发历史证据；由总控以自己合法actor-id/Session认领交付，不依赖原开发Session。无需交付动作时由系统依 acceptanceScope 决定：system 自动完成，user_ui_business 进入待用户验收；用户不得替系统验收技术门禁。

## 5. 合并与推送
总控负责：同步最新远端主分支；合并通过独测的候选 SHA；冲突解决后运行必要测试；推送远端；验证远端主分支包含实际合并提交。
若合并改变候选代码，必须重新自测和独测。
合并失败：保留分支、提交和现场。调用taskctl delivery-failed记录failure-stage、failure-code、原因和下一动作；任务保留“交付中”及总控本人真实占用，展示阻断，合法总控继续处理。taskctl complete核验失败时CLI自动登记同类失败事件。

## 6. 合并后回归与关闭
对远端主分支实际 SHA 执行回归。只有远端包含合并提交、回归通过且版本记录更新，总控以合法controller_ai和自己的Session执行taskctl complete后，才关闭任务并释放占用；核验失败会自动记录阻断原因。

## 状态概览（非独立状态机）
实际合法状态和转换以 server/workflows/wyerp-ai-flow-v1.mjs、正式任务事件及流程文档/00_统一入口.md为准：待确认/待准备/待开发→开发中→待独测/独测中；FAIL回测试失败待修复/修复中/待复测/复测中；PASS总控交付。现有看板标题待执行的列实际上承载待独测、待复测，不是开发可领队列；新的开发待执行列属于P0计划，尚未上线。
`待用户验收` 只能由独测 PASS 或合并后回归核验通过后进入；通用 PATCH、AI/Bearer 身份不得代替浏览器正式用户验收。
每个任务任一时刻只有一个当前执行者和一个下一动作。待交付保留原开发候选/独测证据，但交付执行由总控本人合法身份进行；交付失败不应擅自释放占用。状态变更必须有看板事件，不能只改文字绕过门禁。

**24小时常设异常接管授权**：任何有待办的开发/独测/交付/阻断任务超过24小时没有真实进展，或已合并分支/worktree超过24小时未清理，允许对应角色新窗口用全新actor/Session正式接管。计时以有效状态、真实测试/代码或可信Git合并/关闭为准，查询和心跳不刷新。记录原/新身份、候选SHA、工作区、代次、原资源，防旧Session抢回；无需再问用户，**不等于可以绕过现有API或伪造用户Session**，缺能力由开发最小补足。已完成只接管遗留清理，不重开业务，禁止强删/自动唤醒。

## 异常接管
用户明确要求接管时必须执行，不得以原 AI 未登记失联为由拒绝。记录用户原话、原/新执行者、原/新 Session、任务版本和工作区证据。
不删除原工作区或未提交修改。旧 Session 恢复后不得覆盖接管后的新版本；写入前核对任务版本/接管代次。

## 上下文切换
断点至少包含：任务 ID、状态、负责人、分支、起始/候选 SHA、自测/独测报告、未解决问题、下一动作。新 Session 先读断点和 Git 状态再继续。
