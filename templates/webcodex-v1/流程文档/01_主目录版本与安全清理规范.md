# 所有软件：总控开工前主目录版本核对与安全清理

**适用版本：`2026.11.02-r3`。** 所有接入软件的总控都执行；各项目独立检查自己的代码仓库、软件主目录和本地日志。必须先读 `00_流程与重大更新日志.md` 并核对角色版本。

**新需求先登记**：用户提出需求时先做 `C00_A_REQUIREMENTS`，不得因Git差异漏记；正式开工前再进行版本与清理检查。

## C00_B：已合并版本一致性（任务执行前）

1. 确认**目标软件项目根目录**、用户认可的**唯一软件主目录**及其远端默认分支（通常 `main`）；读取本地默认分支 HEAD、远端默认分支当前 SHA，必要时先安全 `git fetch` 更新远端跟踪引用。**仅比较已合并主分支与本地主目录正式版本**，不把任何任务候选、未合并工作区、临时分支当作正式软件版本。
2. 核对正式软件版本号（如 `package.json`、程序集版本、Python 项目元数据/应用内版本）与远端已合并主分支记录一致。能读取运行实例/部署版本时核实实际进程使用的项目根及版本；若运行版本无法独立验证，标记“运行版本未确认”，不得宣称运行实例已升级。源代码主目录一致不等于运行软件已热更新。
3. 主分支 SHA、正式软件版本不一致，**优先安全同步或记录真实阻断和下一动作**；主目录有脏文件必须保全、备份或分离，再由合法角色受控升级，禁止 `reset --hard`、强制覆盖其他 AI 修改或删除配置。版本未一致时不能开展会改变受影响代码的正常开发/交付；只读盘点、需求记录和必要修复派工可继续。
4. **证据**：项目、目标目录、当前分支、远端已合并 SHA、本地主目录 SHA、双方正式版本号、运行版本/进程（可证实时）、Git状态、实际命令/退出码和结果；写任务断点及本项目操作日志。此检查只证明正式主线一致，不要求取消合法未合并开发任务。

## 最新覆盖：版本核验包含交付和安全资源清理（2026-11-03）

每次总控开工C00_B强制核对远端main、本地主目录main、软件/运行版本，并由真实get/history扫描独测PASS待受控合并、已合并未部署、真正已完成但资源未清理的任务。C00_C按已合并、已关单、工作区无dirty且无AI/Session/Job/PR共享引用、审计/备份有效来逐项判定，**当场使用非强制Git安全命令清理已安全资源，并记录执行和验证结果**；未通过条件的保全并登记owner、原因、下次C00/C07/C08自动重试触发。C06/C07关单前后负责本任务，C08负责历史遗留复扫；不能每次只盘点后把清理责任推给用户。独测未PASS禁止自动提交/合并，主目录脏文件、未知归属分支或任何有人使用的工作区严禁重置和强删。此规则为本地受控文档，真实程序门禁仍由原ROLE-STEPS-SERVER-GATES P0开发、独测与正式交付后生效。

## C00_C：自动安全清理与旧候选无损归档（C00_B之后；不再等待闲时）

1. **每次开工必须实际处理**已合并/关单分支、已完成任务的旧候选、工作区和占用；先核对正式独测PASS的冻结SHA与当前main、任务是否真正完成、是否有新候选替代/补丁等效、工作区dirty与AI/Session/Job/未关闭PR/共享引用以及历史证据备份。安全的当前轮次处理，无法确认的保全登记owner/原因/下次触发；不阻断不冲突的开发任务。
2. 所有条件都通过时，使用既有安全删除（例如 `git worktree remove`、`git branch -d`）清除**本任务**确认可清理的本地资源，并核对结果。远端任务分支额外确认未被其它引用使用方依赖后才按正式授权删除。禁止 `-D`、`--force`、`git clean -fd`、`reset --hard` 或按名称批量删工作区/备份。
3. **已完成任务的旧候选非main祖先**：即使Git `--merged`不包含它，也不能简单判为还要合并。先核对原QA PASS候选/后续替代SHA和`git cherry`等效关系：已替代或等效且无引用时，非强制`git branch -m`从活跃`feat/fix/docs`移入本地`archive/`并记录原/新ref和原提交SHA；仍有独有改动的保留供原责任复核，不因关单自动merge或删除。归档不等于删除/正式交付，不操作远端分支；该规则补足旧已完成任务‘未合并’假积压。
3. 对不满足证据条件的项目，列出待清理资源及阻断原因、责任角色、下次复核条件；保留原成果，**不能把存在 worktree 或未合并候选直接判作无效版本**。不冲突任务可以继续派工，需污染主目录的任务必须先处理确切写入冲突。
4. **证据**：清理前后工作区/分支、远端合并祖先验证、工作区状态与未跟踪文件、关联任务状态/权限/Job/PR、清理命令/退出码或保全原因、实际日志。运行中服务不随意重启。

**通用路径规则**：本规则由每个软件自己的 `流程文档/` 管理，操作日志落在该软件目录已有日志系统；如已有 `data/logs/` 可沿用，缺少时使用 `logs/`，禁止跨项目集中或只在聊天记录。
