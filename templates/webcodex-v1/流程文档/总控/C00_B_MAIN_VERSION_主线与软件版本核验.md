# C00_B_MAIN_VERSION｜任务执行前正式主线与版本核对

- **准入**：`C00_A_REQUIREMENTS` 已记录或核查需求；角色版本已核对。正式认领、编码、交付之前需执行本检查。
- **执行**：按 流程文档/01_主目录版本与安全清理规范.md，仅比较远端已合并默认主分支SHA、本地唯一主目录正式主分支SHA及两端正式软件版本；可查时还需核实运行实例的真实版本、进程根和健康。未合并候选或开发worktree不能作为正式主线。发现差异先安全处理/登记，不强制reset覆盖他人未提交成果。
- **最新覆盖：版本首检包含交付链**：每次开工/继续必须在核对主线SHA和运行软件版本后读取任务历史，输出独测PASS待总控合并、已合并未部署或未关单、历史已完成但资源未清理的待办。总控对已合法QA PASS的任务立即安排C04→C05→C06→C07串行交付；未PASS的提交不能自动merge或提交，不能把只比main SHA当作完整版本门禁。C00_C必须接续处理已安全可清理的资源，不用用户催促。
- **证据**：项目主目录、实际Git及软件版本、命令/退出码、进程运行版本（能核实时）、脏文件保全和阻断。
- **PASS下一步**：`C00_C_SAFE_CLEANUP`。
- **程序兼容**：现有stepctl未强制C00，只有受控开发独测发布后才能声称自动执行。
