# 07｜全软件 BUG 强制修复与闭环续接规范

> 生效依据：用户 2026-11-05 明确命令「修复BUG必须强制修，否则永远修不完；所有软件都一样，有BUG就强制修」。适用于任务看板和**所有已接入/以后接入统一模板的软件项目**。此处是角色与总控当次可直接执行的权威操作规则；**服务端自动门禁未发布前不得声称已经由机器强制执行**。

## 1. 不得搁置的触发规则

1. 发现有真实复现或可信独测证据的 BUG，**同轮**核对任务注册表已有同根因未完成修复卡；没有则总控立即创建**一张独立最小** `track=bugfix、priority=P0` 的卡，附原失败事件、复现、用户目标、写文件、已知依赖、三轮验证与 BUG 三问；不得暗改已完成/已失败/旧阻断任务的范围。相同根因已存在卡就链接，禁止无穷重复建卡。
2. **强制排在普通开发之前**：总控每次启动/继续/发生新 BUG、claim、PASS、FAIL、BLOCK、交付或恢复后，先读取全部项目的 BUG 队列，按「可合法领取且能解锁最多受阻下游」优先，随后其他合法 P0 BUG；同优先级兼顾用户明确加急和等待时间。所有可并行 BUG 一次正式 `controller_dispatch`，有无开发者领取都记录跟踪责任与下一触发。不是只建卡、只派工或只汇报。
3. 已唤醒的开发 AI 在完成正在执行的小功能并安全保存断点后，**先接原本人 FAIL 返修及可合法领取的 P0 BUG**，再接普通功能。普通功能不得抢占可领取 BUG 的新正式 claim；多人使用不同 actor/Session 和独立 worktree 并行，单 actor 一次一项，唯一独测、main 合并串行。已有执行中的任务不粗暴中断或覆盖。
4. 合法领取后必须实干：`get/history/guard → preclaim-report → claim → 独立 worktree → 最小修复 → R1/R2/R3 自测 → 唯一独测 → 总控受控 main 合并、运行版验证、正式 complete`。无真实用户命令不得自动唤醒外部 AI 会话；不把派工/预开发/WIP/聊天声明当正式领取或完成。

## 2. 遇到阻断必须修根因，不得无限等待

1. 任一 BUG 的正式领取或开发遇到 409、步骤断点、前置、工作区占用、环境、测试、交付失败：当轮记录真实错误码、任务号、actor/Session、事件、相关资源、机器恢复条件；总控回溯共享根因，已有最小 BUG 则提高派工优先级，没有则新建**独立 P0 根因卡**，与原 BUG 建事件关联；不得原地无限重试、等待用户再次说「继续」、更不能伪造成功。
2. 当前 BUG 受硬前置、STOP、HOLD、合法占用或未完成的唯一独测门禁限制时，**该卡必须保持真实阻断状态**，系统/角色立即转向同项目或其它已接入项目下一张合法 BUG；没有合法可领 BUG 才允许有明确阻断原因、责任、解阻条件、下一次触发的断点。待前置关单/占用解除后自动重算候选，强制再次进入首选队列。
3. 解阻必须由可信机器事实及正式事件触发：验证事前派工、历史新轮次、硬前置、STOP/HOLD、唯一测试/候选 SHA 和角色独立性；不得靠补备注、假 claim、强改「已完成」或擅自删除历史。「强制」只表示**强制处理与闭环追责**，不是绕过安全权限、用户停止、独测或系统门禁。
4. 无法由当前已发布引擎自动恢复的阻断类型，必须另建能被最小独立验收的 P0 自动恢复卡；上游门禁 BUG 修好后，旧阻断必须由可信系统自动复核恢复，不能由用户逐张清列。

## 3. 三角色强制职责（全部项目通用）

- **总控 C01/C02/C03/C08**：一次性发现全项目 BUG、核验证据和已有同根因卡、建立最小 P0 卡、逐张正式派工与读回；把受影响原任务关联；依赖根因先修；开发无人领取/独测待排/交付失败都持续跟踪，已唤醒期间不等待用户指名；跨会话持久保存 BUG 总清单、状态、责任与下一动作；有合法 QA PASS 待交付的 BUG 自己优先处理。
- **开发 D01/D09**：每次被唤醒或 handoff 后主动扫 BUG 并优先合法领取；旧版门禁拒绝时报告真实失败，处理本 actor 能合法修的阻断、继续下一合法 BUG；可合法复用隔离 WIP 但必须最新 main 下重新合法 claim、三轮自测并交 QA。不得因「无人派给我」或 409 停摆全部任务。
- **唯一独测 Q01/Q04**：合法待独测/复测的 P0 BUG 优先于普通功能；三轮从核心、负向、回归独立核实。FAIL 保存证据退回原开发并由总控重排修复；QA PASS 只交总控，不自合 main、不自关单。

## 4. 系统生效与验证

- 即日起角色操作按本规范执行，**现有程序若不能强制保证 BUG 排队、claim 优先、失败追踪/回流、跨项目同步，必须由独立最小 P0 程序任务补门禁**，通过开发三轮/唯一独测/总控发布后才能宣称所有连接软件的系统自动生效。
- 新软件接入必须通过当前权威 `流程文档/` 和 `templates/webcodex-v1/流程文档/` 的逐文件哈希一致性校验；旧项目若保存过时拷贝则按合法规则升级，不自动覆盖其他项目自行修改的任务或代码。
- 修复关单必须完整回答：①问题真实解决了吗？②同类问题下次是否会复现，有哪些正负/回归门禁？③原任务、关联阻断及后续流程是否正常？未验证项写正式关联卡及状态，禁止说「全部好了」。

**禁止自动唤醒 AI**：强制修 BUG 是已唤醒角色必须主动处理和系统必须阻止普通任务抢先领取，不自动唤醒或自动发送消息给其它开发、测试、总控会话；只有用户手动唤醒的角色才能依法执行真实claim。
