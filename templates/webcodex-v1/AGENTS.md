# AGENTS.md — WebCodex 项目通用规则

目标：按任务完成真实代码、测试和 Git 交付；不要只写计划或报告。

三角色完整职责唯一来源：项目根目录 `总控AI.md`、`开发AI.md`、`独立测试AI.md`。`docs/governance/` 旧路径仅用于兼容，不能再维护第二份角色正文。

## 优先级
1. 当前用户明确指令
2. 本文件与 WORKFLOW.md
3. 当前任务验收条件
4. AI 自行判断

用户明确要求异常接管时，必须按接管流程执行；不得仅因原 Session 未先登记失联而拒绝。保留原记录、未提交成果和证据；不得伪造授权或破坏数据。

## 每次开始
1. 每次启动、接管或换 Session，读取本文件、WORKFLOW.md、开发 AI 角色规范、**当前主计划、任务历史、最新断点与失败报告**，并实际核对 Git/Job/Session；未完成不得改代码。
2. 检查 Git 分支、工作区、远端和任务占用。
3. 确认任务范围、依赖、负责人、验收条件。
4. 保护已有修改；不重置、不清理、不覆盖无关文件。
5. 一次只执行一个任务，不擅自扩展范围。

## WebCodex 执行规则
- 只使用当前会话实际提供的工具；先看工具说明，不猜工具名、参数或项目命令。
- 文件读取用读取工具；单条程序命令用进程工具；相关 shell 操作用 shell。
- 不把独立的验证、提交、推送、发布动作串成一个命令。
- 长任务使用可观察 Job，并持续观察到完成；不能把“已启动”说成“已完成”。
- 每完成一个**最小可验证小功能**立即落盘代码、执行对应检查、更新 `data/taskboard/checkpoints/<TASK-ID>.md` 并登记 `checkpoint_saved`，核验成功才进入下一小功能；测试失败、工具异常、Job 阻断、上下文切换和退出前同样保存。新会话先读断点并核对现场，不依赖旧聊天记忆。完整细节见 `docs/governance/开发AI工作规范.md`。

## 质量与 Git
- 自测证据必须绑定被测 Git SHA。
- 独立测试必须由不同执行身份完成，并实际测试同一个候选 SHA。
- 失败回到原开发者；修复后重新自测、重新独测。
- PASS 后由原开发者合并、推送并执行合并后回归。
- 只有远端主分支包含合并提交且合并后回归通过，任务才可关闭。
- 不允许伪造 PASS、复用旧 SHA 的 PASS、仅本地合并就宣称交付。
- 失败必须记录原因、负责人和下一动作，不允许无人负责地停在“交付中”。

## 用户回复
只报告已验证事实：修改内容、测试结果、SHA、下一责任人和下一步。遇到问题先处理，不以长篇报告代替执行。
