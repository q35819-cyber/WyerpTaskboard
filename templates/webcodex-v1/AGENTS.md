# AGENTS.md — WebCodex 项目通用规则

**所有角色每一步必须实时向用户汇报**：操作前在当前聊天写任务/角色/步骤、Ponytail实际读取路径与模式、工具及具体动作；操作后立即写工具返回/退出码/异常，步骤结束写PASS/FAIL/BLOCK、断点与日志证据、下一步。不能只在最后总结或仅存看板事件，不得虚报已经读取Ponytail。详见 `流程文档/04_逐步聊天汇报与证据校验规范.md`；现有程序没有可靠的聊天送达回执，系统步骤证据不等于用户已看到，程序门禁尚需P0开发。


**强制启动第一步（所有 AI / 每次新会话、接管、续办）**：先完整读取 `流程文档/00_流程与重大更新日志.md` 的当前生效版本与未读重大变更，核对 `流程文档/00_统一入口.md` 和本人 `流程文档/<角色>/00_角色入口.md` 的 **规则版本** 均匹配；版本不一致/日志缺失时，暂停领取和修改，重新读取最新统一入口、角色步骤、专项规范、任务历史及断点，完成合法版本对齐后才开工。此检查优先于旧聊天记忆及旧根角色文档。每次源码/配置/文件增删改及软件运行时 CRUD 都必须按 `流程文档/02_增删改操作日志规范.md` 写入**对应项目目录下**的持久日志，失败亦留痕；不得只写聊天、仅凭Git或向其它项目集中存储。


目标：按任务完成真实代码、测试和 Git 交付；不要只写计划或报告。

**任何代码开发、修复、重构、依赖选型或代码审查必须先实际读取项目内 `.agents/skills/ponytail/SKILL.md` 并遵循 full 级别；这是强制门禁，不是建议。** 模板应用到新项目时需一同复制本模板的 `.agents/skills/ponytail/SKILL.md`；若目标项目已有正确版本，直接复用。没有此文件则停止写代码并由总控补齐，不得口头宣称已使用。开发自测报告简短记录已复用模块、调用方、最小 diff 和必要测试，不新造验证平台。

三角色唯一职责在当前项目的 `流程文档/总控/00_角色入口.md`、`流程文档/开发/00_角色入口.md`、`流程文档/独测/00_角色入口.md`。开工第一份必读 `流程文档/00_流程与重大更新日志.md`，核对版本；根目录旧角色文档不是活动权威。

## 优先级
1. 当前用户明确指令
2. 本文件与 WORKFLOW.md
3. 当前任务验收条件
4. AI 自行判断

用户明确要求异常接管时，必须按接管流程执行；不得仅因原 Session 未先登记失联而拒绝。保留原记录、未提交成果和证据；不得伪造授权或破坏数据。

## 开源复用强制要求

开发碰到不会实现、同一方案连续失败或想从零写大模块，先查已有代码，再检索开源同类软件的**实际源码和测试**，核对版本、许可证和适配成本。可用且合法的代码应**移植进本项目实际源代码**并保留原许可、测试和固定 Git 版本，长期使用；只写外部地址、截图或参考报告不算实现。只搬当前目标必要部分，不引入整个新框架。总控按此派工，独测只核验本任务内的实际复用与测试；无合适开源时说明检索结果后用最小实现，不能无限阻断交付。


**所有接入软件的总控开工门禁**：先按 流程文档/总控/C00_A_REQUIREMENTS_需求记录与讨论.md 登记用户讨论需求；仅在用户明确新设备或真实环境异常时，由总控执行 流程文档/总控/C00_D_ENVIRONMENT_新设备与环境异常恢复.md 并按三种不同角度自测；正式认领/开发/交付前再核对 C00_B_MAIN_VERSION_主线与软件版本核验.md 和 C00_C_SAFE_CLEANUP_无效与已合并版本清理.md，随后进入C01_SCAN。保全主目录未提交与其它AI工作区；具体以最新流程文档/为准，不假报程序已自动实现。

## 每次开始
1. 每次启动、接管或换 Session，先读本项目 `流程文档/00_流程与重大更新日志.md` 并校验本人角色最新版本，不匹配重读全部受影响规则/任务断点；再读取本文件、WORKFLOW.md、对应角色规范、**当前主计划、任务历史、最新断点与失败报告**，并实际核对 Git/Job/Session；未完成不得改代码。
2. 检查 Git 分支、工作区、远端和任务占用。
3. 确认任务范围、依赖、负责人、验收条件。
4. 保护已有修改；不重置、不清理、不覆盖无关文件。
5. 一次只执行一个任务，不擅自扩展范围。

## WebCodex 执行规则
- 只使用当前会话实际提供的工具；先看工具说明，不猜工具名、参数或项目命令。
- 文件读取用读取工具；单条程序命令用进程工具；相关 shell 操作用 shell。
- 不把独立的验证、提交、推送、发布动作串成一个命令。
- 长任务使用可观察 Job，并持续观察到完成；不能把“已启动”说成“已完成”。
- 每完成一个**最小可验证小功能**立即落盘代码、执行对应检查、更新 `data/taskboard/checkpoints/<TASK-ID>.md` 并登记 `checkpoint_saved`，核验成功才进入下一小功能；测试失败、工具异常、Job 阻断、上下文切换和退出前同样保存。新会话先读断点并核对现场，不依赖旧聊天记忆。完整细节见当前项目 `流程文档/开发/00_角色入口.md`。

## 质量与 Git
- 自测证据必须绑定被测 Git SHA。
- 独立测试必须由不同执行身份完成，并实际测试同一个候选 SHA。
- 失败回到原开发者；修复后重新自测、重新独测。
- PASS 后由总控以合法身份合并、推送、升级唯一主目录、执行回归/安全清理/关单；开发只负责开发自测交独测。
- 只有远端主分支包含合并提交且合并后回归通过，任务才可关闭。
- 不允许伪造 PASS、复用旧 SHA 的 PASS、仅本地合并就宣称交付。
- 失败必须记录原因、负责人和下一动作，不允许无人负责地停在“交付中”。

## 用户回复
只报告已验证事实：修改内容、测试结果、SHA、下一责任人和下一步。遇到问题先处理，不以长篇报告代替执行。
