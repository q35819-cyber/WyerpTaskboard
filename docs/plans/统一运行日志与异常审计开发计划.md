# 统一运行日志与异常审计开发计划

> 修订：2026-10-07；WTB-DOC-CLEANUP-001。功能关联WTB-SENTINEL-001 / WTB-WAKE-001。
> 本计划保留实现范围与验收，删除过期版本、PID、运行开关和通过率快照。日志字段、保留、脱敏和异常分类只维护于 `docs/governance/日志与异常审计规范.md`。

## 1. 目标

保留专项日志的模块细节，统一总日志提供跨组件时间线。用户/AI能够判断哪个任务、组件和动作在何时申请授权、执行、失败、恢复或被安全阻止，而不是只能看到泛化“异常”。

日志不是任务状态的第二真值，也不复制被管理项目业务正文。当前任务状态仍由注册表决定，配置值从 `config/system-event-log.json` 读取，历史测试与运行证据按各自版本保存。

## 2. 实现范围

| 模块 | 必须可追踪的事件 |
| --- | --- |
| 服务与CLI | 生命周期、参数/连接失败、未捕获异常、动作结果 |
| HTTP/API | 认证、输入与业务拒绝、服务异常；仅安全元数据 |
| 任务扫描 | 扫描、项目源失败、锁/存储/调度与候选异常 |
| Chat Wake服务端/扩展 | 握手、版本、epoch、通信、storage、heartbeat及候选协作失败 |
| Windows-MCP与GPT执行器 | 会话、白名单、审批、执行开始/结果、platform_safety与接管中断 |
| 健康监控/视觉 | 诊断、恢复意图、执行后的状态复核、证据保存/清理失败 |
| 全局控制台 | 启动、输入观察、轮询、操作、离线fallback与响应异常 |
| 任务事件/事务 | journal/segment校验、崩溃窗口、不一致与恢复 |
| 测试/验证 | 测试开始、结果、失败摘要与版本绑定 |

关键异常进入总日志，专项数据保留独立细节；同流程通过trace/task/detection/action_fingerprint关联，不用聊天文字替代持久化记录。

## 3. 存储与查询

统一总日志入口为 `data/runtime/system-events/YYYY-MM-DD.jsonl`；认证查询为 `GET /api/runtime/events`，运行状态提供最近错误摘要。专项路径与标准字段见唯一日志规范，不在本计划复制一份可漂移的表。

浏览器离线记录最小fallback，恢复后按规则flush；控制台服务不可达保留本地fallback。高频相同异常限频/聚合，仍保留首次/最近时间、次数及恢复结果。日志写入失败fail-soft；GUI上传异步，不能阻塞用户界面。

## 4. 安全与恢复

日志不得保存凭据、完整Authorization、Cookie或完整聊天正文。大对象摘要化、限制大小，异常截图单独按策略保存，不内嵌到总日志。

禁止未说明的静默吞错；仅不影响真值的预期解析回退、允许不存在文件或best-effort清理可按规范显式LOG-IGNORE。损坏事件/事务不得自动猜测覆盖正式状态，按项目隔离、告警和受控恢复。

## 5. 验收与证据

验证脱敏、大小/保留策略、序列化、写失败降级、离线恢复和关键异常覆盖；各涉及模块至少有可追踪成功/失败路径。关联现有 `tests/system-event-log.test.mjs`、`tests/logging-coverage.test.mjs` 与受影响定向测试；真实运行写入/查询必须另有现场证据。

代码改动按风险完成语法、定向及适用完整回归；纯文档修订只做静态检查，不启动运行链路。报告明确版本、实际命令、日志事件、未测项和资源恢复；某历史版本“0失败”不能作为本轮或当前浏览器日志上传已通过的证明。

## 6. 变更边界

本计划不授权启用扫描、Chat Wake、健康监控、控制台或无人值守，也不授权刷新GPT。版本、当前开关和已部署状态只从实时源及带时间快照核验。未来功能改动按正式任务、资源与测试流程执行。
