# 任务看板异常接管：用户对话直接授权

- 来源：2026-10-09 用户明确要求：用户在任何地方允许异常接管，就应执行异常接管流程，不再要求进入任务看板点击授权。
- 任务：WTB-TAKEOVER-CHAT-AUTH-20261009-T1；此计划依据当前用户指令执行，无须再要求同一授权的人工点击。
- 现状：B-10 的 `takeover/allow` 仅允许浏览器 session，taskctl 的 bearer 无法转送用户聊天中的明确授权；`suspected_disconnect` 不能自动授予权限。

## 范围及方案

1. 保留浏览器授权，增加受控的「当前对话用户明确授权」入口。仅已经认证的看板 API 调用者能记录聊天委托；必须附用户原话、授权来源、具体任务/项目范围、会话标识及操作者。不得以 AI 自身建议、历史泛化授权或定时超时生成许可。
2. 执行 AI 接到当前用户明确指令后，在同一会话核查原 owner/session、revision、原执行者是否可恢复、活动 Job/持续写入及资源后，登记疑似失联/执行冲突证据，转送一次性授权，再执行已有 `taskctl takeover`。这三个步骤可由 AI 连续调用，无需用户在看板点按钮。
3. 保留一次性授权、改 owner/session/revision 自动过期、撤销机制、任务阶段不变化、事务/事件审计、无真实停止证据不强抢和正常认领硬门禁。不要放开无授权的 `claim`、普通 bearer/无上下文调用。
4. 新增 CLI 转送入口与 HTTP 验证，补正向、负向和过期回归；更新中央规范的单一权威规则，不碰无关 ERP 或 GPT 自动化控制。

## 安全限制

ChatGPT 原始用户消息没有通过目前的看板 HTTP 协议提供可密码学校验的签名。新入口属于已认证 AI 的**受托治理声明**，不是平台对消息作者的强身份证明；必须将转送者、原文、任务和会话记录为可审计证据。没有可归属当前用户的明确消息或存在否定/歧义时，禁止 AI 擅自调用。对敏感环境可后续增加签名代理/受信 MCP attest，不在本任务伪造该证明。

## 验收与回退

- 用户在当前聊天明确说「允许异常接管 X」后，AI 能不依赖浏览器人工点击执行「核查→suspect→allow→takeover」，并报告结果。
- 无授权、泛化或否定表达、缺任务上下文、旧 revision/owner 变化、重复消费继续拒绝。浏览器原授权可用。
- 实际危险写入未停止时，虽授权也阻断，记录原因；未知结果不重试抢占。
- 可通过撤销聊天授权入口的服务器分支及 CLI 子命令回退，旧浏览器授权保持可用。定向测试及基础检查；独测和正式生效另按看板流程。
