# 全局状态哨兵与人工接管开发计划

> 现行修订：2026-10-07；WTB-DOC-CLEANUP-001。功能任务：WTB-SENTINEL-001，监控界面关联WTB-MONITOR-001。
> 本文是GPT副作用、授权、人工接管和恢复边界的唯一维护入口。删除旧NO-OP审批菜单要求、旧执行器方案和过期版本/PID/通过率快照；不删除历史事故证据，不因此恢复被暂停任务。

## 1. 目标与完成边界

提供一个中文、可拖动、可最小化到Windows通知区域的总控制台，让用户看到当前任务/角色、步骤、目的、最近动作、下一步、异常、恢复依据、授权状态以及是否将操作GPT。任务状态来自注册表，组件观察来自新鲜运行证据，不能在任务执行时误报空闲。

只覆盖普通用户桌面；不承诺覆盖UAC安全桌面、锁屏或系统安全界面，不绕过这些边界。控制台响应性、托盘恢复与用户随时接管优先于置顶展示。

源码存在、脚本能解析、窗口曾显示、真实行为通过和用户验收是不同结论。当前阶段以任务注册表为准，运行版本/开关以当前状态页的采样及重新核验为准，不写永久“已部署/Disabled/PID”。

## 2. 组件职责

| 组件 | 负责 | 不负责 |
| --- | --- | --- |
| Chat Wake扩展 | 页面状态、版本、心跳、最小候选/异常引用、执行上下文协作 | 不直接点击、输入、发送、导航、停止生成、刷新GPT，不自动reload自身 |
| 截图观察 | 在授权范围提供必要视觉证据，辅助识别来源冲突 | 不作为执行权限，不保存完整聊天内容充当任务真值 |
| 看板/总控 | 任务关联、状态聚合、审批/接管、动作去重和审计 | 不以候选或历史ACK冒充正式claim，不复制项目业务正文 |
| ChatgptMcpExecutor → Windows MCP | 唯一执行GPT状态变更的受控链路 | 不绕过授权、输入租约、任务身份或安全阻断 |
| Windows总控制台 | 用户可见状态、暂停/恢复、审批、托盘与输入观察 | 不把UI显示成功当业务动作成功，不阻塞用户操作 |

源码入口：`server/automation-control.mjs`、`server/chatgpt-mcp-executor.mjs`、`server/windows-mcp-client.mjs`、`server/chatgpt-health-monitor.mjs`、`scripts/global-status-overlay.ps1`、`browser-extension/chat-wake/`。这些是实现位置，不是全部当前已通过的证明。

## 3. 授权与生命周期

1. 启动/重启控制台或恢复崩溃后，默认等待人工启动，不从历史无人值守状态自动获得执行权。启动看板服务不等于用户授权GPT动作。
2. 未启用无人值守时，**只有直接改变ChatGPT页面/会话状态的动作逐次审批**：新聊天、切会话、输入/发送、重试/继续、停止生成及最后手段刷新。审批必须明确目标、动作、依据与影响；未获批不得先执行后补记录。
3. 无人值守必须有用户显式选择及绑定版本的有效测试门禁；也只允许白名单内动作。暂停、人工接管和平台安全阻断始终优先。
4. 代码、文档、测试、服务操作、只读截图和非GPT诊断不因总控额外弹审批，但仍必须在各自任务授权及资源范围内；本条不是通用执行授权。
5. 手工MCP独立通道不隐式启用自动系统；其实际GPT动作同样不能绕过本计划的安全边界。

## 4. 人工接管

- non-injected键鼠输入按人工接管处理；injected标志不能单独证明来源，必须与本系统短时input lease的动作/目标/时间窗关联。未知输入、来源冲突或监视器异常时fail-closed。
- USER_TAKEOVER的作用域为交互自动化：停止新的鼠标、键盘、GPT交互，自动取消unattended；不能因为用户动鼠标就终止后台代码、测试、文件写入和服务。停止后台工程任务需要另行明确授权。
- 用户明确恢复才可继续交互，不能“静置一会儿自动恢复”。恢复按钮自身的合法点击必须避免再次触发无意义接管循环。
- 运行态不得把短时lease当成不可伪造的输入来源证明；存在竞争或未知动作时以安全暂停为准。

## 5. 异常恢复与刷新最后手段

恢复顺序固定为：**观察/识别 → 诊断与新鲜证据 → 当前授权/接管复核 → 受控MCP动作 → 状态复核 → 记录结果/继续同任务**。扩展只提供观察或恢复意图，不自行处理GPT。

正常generating不可强制切会话或刷新；不能为了修心跳、满足时延或凑测试结果打断用户工作。processing_delayed和execution_error须二次确认，确认后仍不授予动作权。重试/继续、停止→继续在当前会话按已批准范围执行，次数与熔断按配置，不能并行启动多条恢复链。

普通stale、candidate停滞或composer缺失只做诊断，不构成刷新理由。只有明确execution_error/processing_delayed/generating_stalled等异常、常规恢复已经耗尽且证据仍新鲜时，才可提出刷新；刷新仍需当前有效授权，并受人工接管与平台安全门禁约束。不得为测试主动制造无限刷新，不能把旧错误或历史耗尽记录反复消费。

结果未知先查动作/页面/日志，不盲重发。恢复后必须确认页面与heartbeat可继续工作、原task/detection未丢失、没有重复claim/ACK；仅MCP工具返回成功不能单独证明恢复成功。

## 6. 动作去重、日志与隐私

同一action_fingerprint从审批消费到执行结束保持in_flight，不能在执行中再次弹授权。记录申请、允许/拒绝、执行开始、成功、失败、安全阻止和接管中断；平台阻止保留platform_safety分类，不通过换通道规避。

trace、task、detection与动作指纹关联到统一总日志和自动化专项日志，字段与脱敏只维护于日志规范。关键异常不得静默吞掉，日志失败不能再次打崩业务。

异常截图仅在授权诊断范围落盘，默认保留24小时并按策略清理；正常周期观察不保存原始截图。不得在报告/日志保存Token、Cookie、完整聊天正文或无关隐私。

## 7. 控制台交互与稳定性

唯一用户可见主窗为“Wyerp 总控制台”，中文状态与高对比度文案，支持拖动、最小化到托盘、同进程恢复、暂停、明确恢复和真实GPT动作的允许/拒绝。UI规则引用页面布局规范，不保留已移除的NO-OP审批自测入口要求。

网络轮询/输入事件上报不能阻塞UI线程；超时或连续失败时应按安全策略降级，撤销遮挡风险并允许托盘恢复。状态来源矛盾应显示具体来源与未知项，不取最乐观结果。未知实际活动任务时不能宣称全局空闲。

独立计划任务/VBS/PowerShell入口的启动、单实例、进程生命周期须用当前源码及真实环境验证；不以计划任务LastResult=0或旧截图替代进程和交互证据。未获授权不恢复已禁用的真实计划任务。

## 8. 验收工作包

P0包括：正常生成不误恢复；人工鼠标/键盘及未知注入接管；暂停/恢复与无人值守边界；同动作单次审批；MCP执行后复核；原task/detection断点续跑；组件故障fail-closed；全中文、无阻塞、托盘多轮隐藏/恢复。

另覆盖多显示器、Chrome/扩展/MCP断连、截图失败、日志fallback、服务/哨兵重启与版本漂移。测试只能在明确范围、资源与授权下进行，生产操作不为凑用例扩大。

每组报告包含实际版本/配置、命令或页面步骤、预期/实际、trace/截图路径、未测项、资源恢复和是否触碰GPT。核心测试入口为 `docs/项目级核心功能测试需求.md`；独测/用户验收不足时保留缺口，不复用历史“通过”快照。

## 9. 已知执行边界

WTB-SENTINEL-001本轮只读核验仍HOLD且存在stop请求、旧测试身份字段；不能把旧身份解释成新执行权，不恢复、不接管、不清理他人资源。该事实的采样与证据见本轮文档清理报告，不用本段替代下次实时复核。
