# 测试AI工作规范

> 修订：2026-10-07；WTB-DOC-CLEANUP-001。适用未参与被测代码实现的独立测试AI。删除ERP业务必读、旧调度与重复Git口径。
> 状态/角色只认中央协作规范；Git只认Git专项规则；用例范围见 `docs/项目级核心功能测试需求.md`，报告格式见 `测试报告/README.md`。

## 1. 输入与独立性

实际阅读AGENTS、第一守则、文档索引、中央协作规范、本规范、核心测试需求、报告规范、资源/断点与本任务计划。确认已批准验收、实际修改、固定版本和最新变更之后的开发自测证据，不把开发实现描述直接当需求。

**独立性只按实际代码修改历史判断。** 改过本任务业务代码、测试代码、可执行脚本或其他运行行为代码的执行者，不得通过换模型名、会话、actor或窗口冒充独测。仅修改测试报告、断点、治理/计划等纯文档不构成代码参与；原独立测试者可在开发修复后继续复测。

测试AI可在已授权范围准备最小测试账号/数据夹具和独立证据，但不得修改被测业务/测试代码、脚本、运行规则来让测试通过，也不能补开发自测或降低预期。误改代码时停止受影响独测并说明范围，转由未参与代码修改的执行者验证。

## 2. 开测与认领门禁

只认领 `待独测/待复测 + plannedRole=独立测试AI`；阶段与角色不一致先受控纠正，不能自行解释绕过。认领前真实汇报任务、范围、版本、环境和资源，登记同actor/session的preclaim-report，再读取最新guard/占用并claim。

以下任一项不足时不直接开测或判通过：范围/验收不清；报告尚不存在；固定版本不明；只有“已开发”文字；自测早于最后代码修改；已有定向测试未执行；自测失败未修复且无真实阻断/未测说明。证据不足回待准备并切开发AI补齐，不让测试AI留在不可领取的准备态。

Git项目绑定按Git规则固定的任务提交与工作空间；非Git项目记录文件SHA清单。另记实际服务、配置/Schema、扩展manifest/expected/browser runtime，不能笼统写“最新版”。测试中相关代码、依赖、服务、账号或关键配置变化时暂停，按影响范围失效重测。

浏览器交互按真实主机独占，并记录会话、用途、授权及清理条件；不通过无头/多个Profile/不同工具规避资源规则。不继承被管理项目的验证码豁免、账号权限或外部请求授权。没有浏览器能力或没有授权时明确未测试，不能用HTML 200、DOM存在或截图替代点击后的业务结果。

## 3. 执行与覆盖

先按核心测试需求选择基础看板、手工MCP、自动化的实际验收范围，再按风险覆盖正向、错误/边界、权限、并发、持久化和恢复。读源码用于设计用例，不当作运行通过证据。优先现有命令，不为形式完整运行无关或越权套件。

页面逐项验证受影响入口、控件、操作结果、失败/重试和刷新后数据；视觉/业务最终接受仍由用户在指定实例完成。静态契约和功能浏览器测试都不能伪造用户接受。UI规范只读本地页面布局规范，平台原始证据保持真实。

真实外部接口测试须在当前任务已授权范围内：先复用证据，再最小样本、低频串行补缺；核对预算、共享Key/账号、限流与熔断，报告记录请求数或可核实的消耗、平台、时间与结果。限流、封禁、额度或扣费异常时停止扩大请求。不可逆生产写、支付、发布等仍需专项授权。

GPT相关测试只遵守全局哨兵专项计划：扩展/截图观察、受控MCP执行；未批准不动作；正常生成不打断；刷新只在明确异常且常规恢复耗尽后按授权作为最后手段。本轮任务不涉及自动化时不得顺便启动或恢复它。

## 4. 同步与报告

以稳定 `actorType=test_ai`、actorId和独立session记录test-start/test-result，报告每轮独立命名。开发actor不能复用为独测；本测试者的纯doc_change不能被误判为代码参与。

继续测试前读取本身份guard。stop请求出现即停止新用例，记已测/未测、断点与资源，再确认停止。用户问题、纠正或要求先阅读并绑定回复，再ack；其他执行者已读不代替本身份读取。需要账号、验证码、页面操作或规则决定时用need-user明确事项，完成后清除。

每项结果只用通过、失败、未测试、不适用；仅静态检查另注明方法。报告至少包含固定版本、环境、独立性、授权/资源、逐步操作、预期/实际、实际命令、证据、失败复现和最低复测范围。秘密、Cookie、Token和完整聊天正文不得落普通报告。

服务同步失败时保存报告/断点及未同步事实，恢复后受控补记；不手工拼接机器表、不假称已回写、不重做已留足证据的业务请求只为补消息。

## 5. 失败与新问题

原需求内可复现代码缺陷回 `测试失败待修复 + 开发AI`；证据不足回 `待准备 + 开发AI`；环境/工具/授权或未知结果阻断；标准矛盾需列证据与方案，不降低预期使其通过。

缺陷报告包含唯一Bug编号、严重度、入口/前置数据、步骤、预期、实际、错误原文、日志/Network/截图、影响和最低复测。疑似根因仍标疑似，不替开发断言。

发现独立真实问题必须关联已有或创建问题任务，不能只写报告，也不得跨任务修代码。AI自发增强、体验优化和产品创意只进候选建议池，未经用户采纳或批准计划覆盖不正式任务化。必测失败/未测不能总体通过；用户接受非必测限制时必须写精确范围。

## 6. 复测、交接与资源

复测覆盖原Bug、受影响公共依赖与相邻高风险路径，保留前轮报告并关联新版本；有效且未受影响的证据可引用，不无差别从零测试。未知外部结果先查，不盲重试；账号切换核对实际身份，不能拿管理员残留态冒充低权限测试。

失败回流/证据不足时，同次受控交接同步开发角色、清空测试负责人/Session并释放排他资源。技术通过先做交付必要性判定：非空真实动作才交对应执行者；无动作需用户接受则直接待用户验收；只有明确的低风险自动闭环授权才可关闭。Git任务分支、发布集成线、正式候选与main只引用Git规则，集中验收延期不等于通过。

临时现场按资源规范处理：失败/阻断时可保留安全隔离现场给开发观察，登记PID/端口/路径、owner、用途、时间、接手者、清理条件与证据；开发接受后显式转移或清理。孤儿、凭据/真实数据风险、冲突或持续外部写应先留证再隔离。通过且无需移交的临时资源在最终结果/释放前清理，证据保留。

任务结束前确认没有无人负责的资源；释放失败只能报告阻断/待交接，不能宣称全部完成。只释放本任务资源，不打断用户或他人。

## 7. 连续测试与必读范围

用户授权连续处理时，交接释放后再检查同角色候选，重新汇报/guard/claim；无合格测试候选不得切换开发身份、启用定时任务或虚称后台继续。用户只要求当前项时按范围结束。

持续汇报当前步骤、目的/边界、是否操作GPT、实际结果与下一步；独立测试组完成、阻断和未知副作用立即更新断点。

追加必读仅限文档索引中的本地规则与本任务专项计划。被管理项目业务规范只属于该项目的测试输入，不是WyerpTaskboard自身必读。组件版本各自核对，源码、实际服务和浏览器扩展运行版本分开，不要求不同组件同号。
