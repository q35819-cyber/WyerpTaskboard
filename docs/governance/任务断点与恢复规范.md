# 任务断点与恢复规范

> WyerpTaskboard 本地权威副本
> 本文件已迁入 D:\WyerpTaskboard，用于任务看板自身开发/测试/协作治理。
> 对任务看板自身而言，本地副本为当前权威入口；erp-x20 中来源文档仅保留历史与被管理项目溯源，不再作为运行前置依赖。


> 现行规范，2026-09-28。目标：恢复有证据的最近进度，不从头重复工作，也不跳过版本变化所需回归。

## 1. 文件与职责

任务使用 `任务进度断点/` 目录下以实际任务ID命名的 Markdown 文件；也就是“目录 + 实际任务ID + `.md` 扩展名”，这里的任务ID是占位概念，不要求项目存在名为“任务ID.md”的固定文件。顶部维护最新恢复入口，历史断点只追加不覆盖。并行开发与测试使用独立任务/轮次文件，互相引用，不同时改一个断点。

断点不是第二份任务状态台账，也不是正式测试报告。当前阶段与责任人引用待办任务总清单、任务执行与资源占用台账；本文件保存做到哪里、证据在哪里、接下来做什么。

## 2. 何时立即记录

完成一个可独立说明/验证的小功能或测试组时记录；准备高风险或外部副作用动作前、动作已发出但结果未确认时、出现阻断、切换执行者或退出时也记录。不能只在全部成功后补记。

| 子步骤结果 | 必须记录 | 恢复动作 |
| --- | --- | --- |
| 准备执行 | 目标/授权、前置状态、预期变更、请求标识与恢复办法 | 核对尚未执行，再按当前许可继续 |
| 已发出，结果待核对 | 最后已知步骤、外部任务/请求引用、时间、未知项 | 先查结果，禁止重新提交上架/生成/扣费等动作 |
| 已确认完成 | 实际结果、文件/数据版本、测试/响应证据 | 保留完成项，继续下一未完成步骤 |
| 明确失败/阻断 | 原因、现场、受影响与未测项 | 补条件或修复后局部恢复，不假报成功 |

未知结果不等于失败，更不代表可以再试一次。幂等键/请求ID保存必要引用或安全摘要，不记录密码、Cookie、Token和隐私原包。

## 3. 最小字段

任务/父功能ID、最新断点ID、实际执行者ID、观察时间及时区、任务阶段、已完成子项、实际修改文件及SHA/提交、已执行测试和证据、服务/配置/Schema/插件版本的真实观察或未核验、未完成项、唯一下一动作、资源持有与未决操作、风险/授权边界。

“开发完成”“自测通过”“独测通过”“已运行”“用户接受”分别记录证据，不能一个完成勾选代替所有结论。文档只读任务的数据库/浏览器写不适用，不抄旧版本当现测。

## 4. 接手顺序

先读任务身份与占用，确认可接手；再读最新断点及报告，核对目标版本和依赖仍相同；检查旧执行是否停止、未知外呼是否已核实；最后从唯一下一动作继续。没有有效执行权不得仅凭看到断点就操作。

已完成子项若证据有效、依赖未变，不从零重做。公共CSS/组件、接口合同、Schema、权限、配置、运行产物或关键依赖变化时，只重验受影响范围；证据不存在、无法绑定版本或内容损坏时明确待准备/阻断并补必要验证。

## 5. 记录格式

每个断点含：CP编号｜时间/执行者｜本轮完成与未完成｜变更指纹｜测试/运行证据｜未知副作用｜资源状态｜下一步。顶部指针可更新，旧断点不倒改。

历史文件改名按文档名称映射清单解析，不修改旧报告证据以适配新名称。归档已完成任务仍保留断点；未来Bug关联新的修复任务，不清空旧功能成果。
