# 页面布局与交互规范

> 修订：2026-10-07；WTB-DOC-CLEANUP-001。适用WyerpTaskboard Web看板和控制台。本文维护已批准UI目标，不把尚未实现的目标写成运行事实。

## 1. 文案与可读性

用户可见标题、字段、状态、控件、提示与异常统一中文；任务ID、协议、必要产品名与技术标识可保留。底层枚举在显示层解释，原始技术值可在详情/日志保留。文字与背景清晰对比，重要状态同时使用文字与层级，不只靠颜色；常用Windows缩放下仍可读。

## 2. 默认筛选与项目上下文

默认展示全部任务，进行中/已完成已取消只作为用户主动筛选项。页面刷新、重新登录及项目切换不能偷偷把默认值改成进行中；用户已选项目必须在仍有效时恢复，失效时明确提示，不静默切到另一个项目造成任务“消失”。

## 3. 六列显示目标

| 顺序 | 显示列 | 底层状态 |
| --- | --- | --- |
| 1 | 待处理 / 待认领 | 待确认、待准备、待开发、测试失败待修复 |
| 2 | 待执行 | 待独测、待复测 |
| 3 | 执行中 | 开发中、修复中、交付中、独测中、复测中 |
| 4 | 待交付 / 待用户 | 待交付、待用户验收 |
| 5 | 阻断 / 暂停 | 阻断、HOLD |
| 6 | 完成 | 已完成、已取消 |

**实施差异：**测试失败待修复移入第一列的已批准任务为 `WTB-BOARD-FAILED-REPAIR-COLUMN-T1`。本轮只统一文档；所核对源码仍把该状态放在blocked列，页面修复由该任务完成。本表不是“已部署通过”声明，验收不得改表去迎合未修代码。

状态、计划角色、认领与合法流转只遵守中央规范，显示合列不改底层语义。任务卡成员由当前状态映射决定，不能因为candidate未就绪就隐藏；合法开发候选按最新eligible/blockers动态显示待认领，否则待处理。待确认不是开发候选；测试AI只处理待独测/待复测。

待交付和待用户虽然同列，只有真实待用户验收才显示需要用户最终接受；无真实交付动作不制造开发候选。每列最多3项，独立分页，筛选/刷新后页码收敛且完成列可见，不额外增加第7列。

## 4. 任务详情与留言

职责写功能与排除项，进展写证据，不用报告数代替任务管什么。主计划、断点和报告由已登记的受控引用打开，不接受任意绝对路径。

用户留言位于历史事件前，每页3条，正文保持可读；审阅通过/打回与普通留言分开，显示真实状态变化。AI回复关联原留言并显示真实开发/测试角色；只有最新用户留言已回复时主页显示已回复印章，新未回复留言出现即撤下旧印章。

## 5. 总控制台

用户可见名称为“Wyerp 总控制台”，中文展示任务/步骤、最近动作、下一步、异常、审批和是否将操作GPT。优先整合为一个可拖动窗口，支持托盘隐藏/恢复；次级后台组件不长期占用另一个可见窗口。

整合不能牺牲响应性、单实例、人工接管与fail-closed；无法整合须在专项计划说明真实原因。控制台状态与任务/日志不一致时显示来源冲突，不能同时宣称空闲和正在执行。交互授权与恢复策略只引用全局哨兵专项计划。
