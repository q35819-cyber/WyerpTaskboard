# 日志与异常审计规范

> 生效日期：2026-09-30  
> 适用范围：WyerpTaskboard 服务端、CLI、任务扫描、Chat Wake 服务端与浏览器扩展、Windows MCP、ChatGPT MCP 执行器、健康监控、Windows 全局控制台、任务事件/事务、测试与验证。

## 1. 目标

任何会影响**运行、恢复、状态真值、任务流转、权限/审批、MCP执行、ChatGPT状态或用户判断**的异常都必须可追踪。项目采用“**统一总日志 + 专项日志**”双层结构：

- 总日志负责跨组件时间线和第一入口；
- 专项日志保留模块细节和已有业务真值；
- 同一流程优先使用 `trace_id / action_fingerprint / project_id / task_id / detection_id` 串联。

禁止出现“用户看到了异常，但项目没有任何可持久化证据”的状态。

## 2. 统一总日志

总日志固定路径：

`data/runtime/system-events/YYYY-MM-DD.jsonl`

当前配置：`config/system-event-log.json`

- 按天一个 JSONL 文件；
- 默认保留 30 天；
- 单条默认最大 32768 字节；
- 写入失败 fail-soft：日志自身故障不能二次打崩业务；
- Token、Authorization、Cookie、CSRF、secret、password、API key 等敏感字段自动脱敏。

标准字段：

- `at`
- `level`：`info / warning / error / critical`
- `component`
- `event`
- `trace_id`
- `action_fingerprint`
- `project_id / task_id / detection_id`
- `operation`
- `stage / result`
- `error_source / error_code / error_message`
- `service_version / extension_version`
- `pid`
- `details`

## 3. 必须记录的异常边界

以下异常不得只停留在 console、UI、内存状态或聊天文本中：

1. **服务生命周期**：启动/停止失败、超时、端口冲突、身份校验失败、孤儿实例恢复失败、uncaughtException、unhandledRejection。
2. **HTTP/API**：请求异常、业务4xx/5xx、认证失败、非法输入、内部异常；只记录安全元数据，不记录认证密钥。
3. **任务扫描**：scan loop异常、项目扫描失败、候选/状态文件损坏、锁/调度异常、wake失败。
4. **Chat Wake服务端**：配置/版本错误、dispatcher代际冲突、lease/ACK/SSE异常、状态文件损坏。
5. **Chat Wake扩展**：未捕获错误、Promise rejection、storage/message失败、SSE失败、MCP请求失败、heartbeat/ACK/状态轮询失败、版本检查失败。
6. **Windows MCP**：初始化/session失败、工具调用开始/成功/失败、白名单拒绝、快捷键拒绝、工具返回error、超时。
7. **ChatGPT MCP执行器**：审批、执行开始、成功、普通失败、`platform_safety`、USER_TAKEOVER中断、finalize失败。
8. **ChatGPT健康监控**：检测异常、视觉诊断失败、恢复尝试/耗尽、截图保存/清理异常。
9. **Windows全局控制台**：启动、summary轮询、input hook、按钮、审批、键鼠事件上报、服务不可达异常。
10. **任务事件/事务/恢复**：事务不一致、事件损坏、manifest/checksum异常、恢复失败。
11. **测试与版本门禁**：测试开始/结束、失败摘要、版本不一致、门禁失败。

### 3.1 高频异常与UI阻塞的额外要求

- 相同错误在短周期内重复出现时，必须做**退避、限频或聚合**；不能让同一错误每数秒刷一条而淹没其他异常。总日志仍要保留“首次发生、累计次数/最近发生时间、恢复或持续状态”的可审计证据。
- GUI/悬浮窗/浏览器扩展不得因为写日志或上传日志阻塞用户界面线程。网络日志上传必须异步或fail-soft。
- Windows原子文件替换的 `EPERM/EACCES/EBUSY` 属于必须记录的瞬态异常；允许有限重试，但超过重试上限必须升级为error。
- HTTP/SSE一旦已发送响应头，不允许错误处理再次回包；此类异常必须记录为“headers already sent / stream failed”，并关闭当前流。
- 浏览器扩展不得为了“确保存在”而向未授权的任意网站重复程序化注入脚本。权限/注入失败必须有日志，同时修复应优先缩小注入面而不是扩大host权限。

## 4. 专项日志与总日志关系

专项日志继续保留，不由总日志替代：

| 用途 | 路径/存储 |
| --- | --- |
| 统一总时间线 | `data/runtime/system-events/YYYY-MM-DD.jsonl` |
| GPT审批/执行trace | `data/runtime/automation-control/events.jsonl` |
| 任务扫描 | `data/runtime/task-scan/events.jsonl` |
| ChatGPT健康 | `data/runtime/chatgpt-health/events.jsonl`、`last-run.log` |
| 总控制台启动异常 | `data/runtime/automation-control/overlay-startup-error.log` |
| 总控制台服务不可达fallback | `data/runtime/automation-control/overlay-runtime-fallback.jsonl` |
| 浏览器扩展离线fallback | `chrome.storage.local.wyerpExtensionFallbackLogs` |
| 项目任务业务事件 | `data/events/<project>/YYYY-MM-DD-NNN.jsonl` |
| 测试门禁真值 | `data/runtime/validation/npm-test.json` |

关键异常必须进入总日志；专项日志可以保存更多模块细节。

## 5. 浏览器与桌面离线兜底

Chat Wake 扩展无法连接本机服务时：

- 先写 `chrome.storage.local.wyerpExtensionFallbackLogs`；
- 最多保留近期记录；
- 服务恢复后自动 flush 到统一总日志；
- fallback 写入自身失败时至少保留浏览器 console 警告。

全局控制台无法连接本机服务时：

- 写 `overlay-runtime-fallback.jsonl`；
- 服务恢复后统一总日志继续作为主时间线。

## 6. 禁止静默吞错

生产代码禁止无说明的：

- `catch {}`
- `.catch(() => {})`
- `.catch(() => null / [] / {})`

只有以下情况允许不进入主日志：

- 幂等/Best-effort清理失败且不改变状态真值；
- 文件本来就允许不存在的 `ENOENT`；
- 可预期、明确降级的解析探测。

此类路径必须写 `LOG-IGNORE`（或等价明确注释），说明**为什么忽略不会影响状态真值或恢复决策**。不能用 `LOG-IGNORE` 掩盖真实业务异常。

`tests/logging-coverage.test.mjs` 对生产源码进行守卫，新增未标注静默catch应直接导致测试失败。

## 7. 排障顺序

出现未知异常时默认按以下顺序：

1. 先看统一总日志最近 `warning/error/critical`；
2. 用 `trace_id / action_fingerprint / task_id / detection_id` 串起事件；
3. 根据 `component` 下钻对应专项日志；
4. 判断错误来源：业务拒绝、服务、扩展、MCP、ChatGPT UI、`platform_safety`、人工接管或日志系统自身；
5. 核对是否已经恢复、是否处于重复重试、是否需要用户授权；
6. 修复后把结果写回断点/报错记录/测试报告。

查询入口：

- 文件：`data/runtime/system-events/YYYY-MM-DD.jsonl`
- API：`GET /api/runtime/events?limit=200&component=<可选>&level=<可选>`
- Runtime Status：`system_log.recent_errors`

API属于认证接口；未登录访问返回401是预期行为，该请求失败本身也会进入总日志。

## 8. 安全与容量

- 禁止日志保存会话Token、Cookie、密码、密钥、完整Authorization头。
- 不以“方便排障”为理由保存ChatGPT聊天正文。
- 异常截图按其专项策略保存和清理，不直接内嵌总日志。
- 总日志默认保留30天；需要延长时修改配置并评估磁盘成本。
- 大对象必须摘要化；超出单条限制时截断details而不是无限增长。

## 9. 修改日志系统的测试门禁

任何新增生产异常路径或修改日志基础设施，至少需要：

- `npm run check`
- `tests/system-event-log.test.mjs`
- `tests/logging-coverage.test.mjs`
- 受影响模块定向测试
- 最终 `npm test`

本规范不保存某个版本的通过率、耗时或“无新增错误”快照。验证结果必须引用 `测试报告/` 下绑定版本、时间、命令与实际环境的报告；当前日志配置只读取 `config/system-event-log.json`。旧版本通过不代表当前版本通过。

## 10. 与人工汇报的关系

日志不能替代AI主动汇报。用户仍应在聊天/总控制台中实时看到“当前步骤、正在做的功能、是否会操作GPT、结果、下一步”；日志用于事后审计、异常定位和状态真值核对。
