# 开发AI工作规范

> 修订：2026-10-07；WTB-DOC-CLEANUP-001。适用WyerpTaskboard自身开发。删除ERP专属业务必读和旧Git/调度口径；历史报告不作为当前授权。
> 任务状态与角色唯一遵守 `docs/governance/AI协作与任务流转规范.md`，Git唯一遵守 `docs/governance/Git与工作空间协作规则.md`。

## 1. 开工与角色

先实际阅读 `AGENTS.md`、`docs/governance/AI协助第一守则.md`、文档索引、中央协作规范、本规范、资源规范、当前注册表、台账和本任务计划/断点。检查前提、事实/推测、授权、范围/排除项、可判定验收、风险、依赖、固定版本及写文件。

用户已授权且范围明确时继续，不为普通步骤反复索取许可；用户要求只读/先方案时不得实现。不自行创建智能体或跨任务代做。开发AI只主动处理本角色可合法介入任务；测试报告只作为修复输入，不跟踪或替代正在进行的独测。

**先建任务、后开发：**用户确认范围 → 结构化 `taskctl create --project ...`/等价API登记稳定任务ID、主计划、职责、只读依赖、计划写文件和证据入口 → 聊天真实汇报 → `preclaim-report` → 实时guard/占用复核 → 成功claim → 才能第一次修改代码、测试代码、脚本或运行配置。不得手工拼接Markdown机器表，不伪造提前认领。

纯分析及建任务必需的最小治理登记可在claim前完成；紧急安全止损仅允许最小停止/隔离，随后立即补正式任务和真实时序，不能借止损继续功能开发。发现先写后领，停止扩大修改、登记治理纠正并恢复正常流程。

## 2. 工作空间与范围

核对并汇报任务ID、工作空间、Git可用性、分支/基线、worktree和已有修改归属。**每次开发前必须先按《Git与工作空间协作规则》第2.1节取远端最新事实，安全对齐合法本地分支、核查未提交代码与占用，并向用户报备；每次开发后及时按门禁提交、推送、读回同一分支SHA。**非Git填不适用，以文件指纹固定范围；不初始化Git或提交他人的文件来补流程。

只有取得任务执行权及整组必要资源后才写。共享文件执行SHA保护，公共治理索引仅短时串行更新；主计划/源码被其他任务占用时不覆盖、重置、清理或替对方释放。扩大文件组前重新核对资源。规范、消息或台账不能冒充覆盖所有Shell入口的物理硬锁。

前后端及配置变更须在同一已确认功能边界内，不顺手重构、格式化或修改其他项目。看板只写治理字段；被管理项目业务正文/代码由该项目合格执行者在原工作区处理，不能复制进看板形成第二真值。

## 3. 实现、缺陷与反馈

修改前读完整函数及上下游、现有错误记录和失败报告，先复现，再确认根因和最小变更。疑似原因明确标疑似，不能把猜测写成事实。第二次同问题修复失败时重新分析调用链和证据，不重复无依据补丁，不删除或弱化测试换通过。

发现违反已有要求、计划、验收或安全边界的独立真实问题，立即关联已有任务或创建问题任务；不能只汇报，也不能越权顺手修复。AI自发优化/重构/新能力只进 `AI优化建议与候选需求池.md`，默认待用户查看，未采纳不正式任务化。

用户反馈按BUG、新需求、证据不足、规则决策分类，写入对应计划/报告/错误记录并关联任务；events保留原话和处理入口，不替代权威文档。

测试失败留下的临时现场先核对PID/端口/路径、owner、用途、安全状态和清理条件。需要继续使用则显式接管资源；确认不需要后安全清理。有凭据、真实数据、外部写或孤儿风险时先留证再隔离，不能无限保留。

## 4. 本项目保护边界

中文提示明确原因和下一步，稳定机器错误码与原始技术证据保留；显示层可翻译枚举，但不得修改平台原始结果来伪造成功。UI细节只引用本地页面布局规范。

重点保护任务状态真值、项目root路径、认证/凭据、注册表事务、幂等和资源归属。关键异常按日志规范落档；不保存Token/Cookie/完整聊天正文。GPT副作用、人工接管和恢复限制只引用全局哨兵专项计划，不在本规范复制另一套权限。

真实外部接口测试只使用项目已授权、已配置的账号与数据；先复用已有证据，按最小样本、低频串行、预算/限流/熔断约束执行，记录请求数或可核实消耗。出现限流、封禁、额度异常立即停止扩大请求。真实生产写入、收费、发布、购买或不可逆操作仍需专项授权。不得继承ERP验证码豁免等专属历史授权。

## 5. 每批修改后的自测

每完成一个成功的逻辑代码修改事务/可独立验证批次，**在继续下一个独立批次前立即自测**。至少语法/静态检查与受影响定向测试；涉及接口、服务、权限、并发、浏览器、恢复或跨组件合同时按风险补集成/页面/回归。不可用“大事务”跨多个独立功能拖到最后才测。

测试必须来自实际存在的命令和可重复步骤。文件能保存、旧全量通过、源码看起来正确都不是本批次自测；当前无测试时记录缺口并在任务范围内补最小验证。任何失败须修复并复测，或明确真实环境/授权阻断，不能忽略失败后宣称完成。

交待独测/复测前重新确认：最新相关代码变更之后有命令、结果、版本/文件指纹、未测项。之后再变代码则旧证据对受影响范围失效，必须补测。开发不能登记自己的独测通过。

纯文档修改执行命名、引用、规则一致性和证据边界检查，不为凑全量启动服务、数据库、浏览器或GPT。正式发布的完整回归门禁不得被文档自检或少量定向测试替代。

## 6. 状态、留言与交接

每次继续写/测前用稳定actor/session读取guard；有stop则停止新动作，按断点/资源流程确认停止；有未读用户问题、纠正或要求则先真实答复、`reply-user`绑定原问题，再 `ack-user`。仅无需回复的系统通知可说明依据后ack，不能用已读代替回复。

修改成功记录 `changed`，测试开始/结束记录 `test-start/test-result`。注册表写入必须受控，服务失败时保留本任务报告/断点和待同步事实，不手工拼机器表或假称已回写。所有项目型命令显式指定project；未知结果先查，重试沿用稳定operation_id。

开发交接原子完成：目标阶段、`plannedRole=独立测试AI`、清空旧负责人/会话、释放本任务资源。资料/自测不齐不能交接。测试通过后的真实交付、人工验收和Git层级只引用中央及Git规范；无真实动作不空转开发。需要用户配合使用 `need-user` 说明具体事项、入口、步骤与通过标准，满足后清除。

## 7. 连续执行、断点与结束

在用户授权的连续执行范围内，本任务交接释放后重新检查同角色候选；有合格任务再汇报、guard和claim，不继承上个任务执行权。用户只要求当前项、无合格候选或真实阻断时结束；不得擅自开启定时任务或切换测试角色。claim本身不是完成，必须推进到可验证子项、真实阻断或正式交接。

按第一守则持续向用户报告当前步骤、目的/边界、是否操作GPT、结果和下一步。每个独立子项、未知副作用、阻断、交接立即记断点；工具明确未执行的参数错误修正后继续，结果未知先核查，不盲重试。

最终报告写清实现范围、版本/指纹、实际检查、未测风险和资源结果，不能把代码存在、自测、独测、运行、用户验收混为一谈。Git提交、部署、服务操作都依各自授权，不因文档清理自动执行。

## 8. 追加必读

只使用文档索引中的本地实际文件：UI读页面布局规范；GPT/控制台读全局哨兵计划；日志读日志规范与专项计划；手工MCP读独立手工MCP计划；测试读核心测试需求与报告规范；资源/恢复/交付读各自规范。被管理项目的业务文档仅作为其任务输入，不是WyerpTaskboard开工依赖。源码、正式服务和扩展实际版本分别取证；停止与安全留证不因版本不匹配被禁止。
